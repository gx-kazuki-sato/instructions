# Instructions

GPT・Claudeなどに、開発作業や品質確認を依頼するためのMarkdown手順書集です。今回の目的に合う文書を選び、対象リポジトリ・ブランチ・許可範囲と一緒に明示して使います。

## 文書一覧

| 文書 | 用途 | 位置づけ |
| --- | --- | --- |
| [アプリ全体の品質確認・改善](docs/quality-review.md) | アプリを横断して調査・改善・再検証する | 品質確認の依頼内容を整理した手順書 |
| [AI開発作業規約](docs/ai-coding-guidelines.md) | 日常の調査・修正・実装で、作業範囲と完了条件を揃える | 既存の開発指示から再編集した汎用版 |
| [設計先行ワークフロー](docs/design-first-workflow.md) | 複雑・曖昧な変更を、設計と合意から進める | 既存の設計・意思決定・作業記録の指示を統合した汎用版 |
| [テストファースト開発](docs/test-first-development.md) | 不具合の再現や新しい振る舞いを、テストから実装する | 既存のテスト方針から再編集した汎用版 |

## 使い方

1. 今回の作業に合う主な手順書を1本選びます。必要な場合だけ補助文書を組み合わせます。
2. 選んだ文書の実在するURLまたは絶対パスを、対象・制約・完了条件と一緒に渡します。
3. 文書を取得して内容を読ませ、工程別の確認結果と証拠を記録させます。
4. 対象リポジトリに適用される規約があれば、それにも従わせます。存在しない `AGENTS.md` や `CLAUDE.md` を必須の前提にしません。

以下の `<...>` を置き換えて使ってください。

```text
対象リポジトリ：<実在するリポジトリ名・URLまたは絶対パス>
対象ブランチ：<ブランチ名>
手順書：<選んだ文書のURLまたは絶対パス>
今回の依頼：<調査・設計・修正・実装の目的>
許可範囲：<外部接続や操作の制限。コミット・pushは別途指示まで行わない>

手順書を取得して読み、適用される規約と今回の依頼に従って実行してください。
開始時に作業範囲・必須検証・完了条件を確認してください。
事実・推測・未確認を区別し、結果には実行条件と根拠を残してください。
必須検証の失敗・未確認を、承認なしに完了扱いにしないでください。
```

これらは依頼に添える手順書です。モデルの選択、ツールの権限、利用環境の設定を変更するものではありません。すべてを毎回貼り付ける必要はありません。

## 汎用版の扱い

- 開発指示の汎用版は、既存の `AGENTS.md`、`CLAUDE.md`、テスト方針から共通する作業原則を選んで書き直したものです。原本のコピーや、各AI提供元の公式ガイドではありません。
- 元の企業名・案件名・内部URL・個人情報・認証情報・配備構成・業務プロンプトは転載していません。原本の参照情報はローカルの作業記録にのみ残しています。
- プロジェクト固有のコマンド、環境変数、ライブラリの版、PR運用は移植していません。使う際に、対象の実装・設定・規約から確認してください。
- 既存規約と矛盾する場合は、適用範囲と優先順位を確認してください。規約中の実装に関する事実も、古い文書だけを根拠にせず検証します。
- 未検証の仮定を増やさず、再発した問題と検証結果を基に手順書を更新します。未作成のファイルや未確認のURLを、利用可能な参照先として案内しません。
